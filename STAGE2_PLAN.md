# Stage 2 Modernization Plan: Reliability, Build System & Formatting

## Objective
Standardize the developer experience, modularize quality checks, and automate the documentation pipeline to ensure consistent code quality and distribution.

---

## Part 1: Modularize Quality Infrastructure
**Goal**: Establish a single, scriptable interface for all code quality checks (linting and formatting).

### Tasks
1. **Quality Wrapper**: Create `scripts/check.sh`.
    - **Logic**:
        - Check for `shellcheck` and `shfmt` binaries.
        - **Static Analysis**: Run `shellcheck -x common/anything-sync-daemon.in`.
        - **Format Check**: Run `shfmt -d .` (check for diffs/deviations).
        - **Status**: Return exit code 0 only if all checks pass.
2. **Permission**: Ensure `scripts/check.sh` is executable (`chmod +x`).

---

## Part 2: Makefile Modernization
**Goal**: Transition from hardcoded tools to a flexible, target-driven build system.

### Tasks
1. **Tool Variables**: Implement overridable tool paths using the `?=` operator:
    - `PANDOC ?= pandoc`
    - `SHELLCHECK ?= shellcheck`
    - `SHFMT ?= shfmt`
2. **Target: `check`**:
    - Add a `check` target that executes `./scripts/check.sh`.
3. **Target: `doc`**:
    - Add a `doc` target that generates `doc/asd.1` from `USAGE.md` using `$(PANDOC)`.
4. **Dependency Chain**:
    - Make `install-man` depend on the `doc` target to ensure documentation is always updated during installation.

---

## Part 3: Standardized CI/CD
**Goal**: Ensure that the automated pipeline precisely mirrors the local developer environment.

### Tasks
1. **Workflow Generalization**: Rename `.github/workflows/shellcheck.yml` to `.github/workflows/main.yml`.
2. **Unified Command**: Update the workflow to invoke `make check` instead of direct tool calls.
3. **Validation**: Confirm the GitHub Actions runner installs the necessary dependencies (`shellcheck`, `shfmt`, `make`).

---

## Part 4: Repository Hygiene
**Goal**: Clearly distinguish source code from build artifacts and transient files.

### Tasks
1. **Gitignore Update**:
    - Ensure `common/anything-sync-daemon` (the script generated by `make`) is ignored.
    - Ignore editor-specific swap files (`*.swp`, `*~`).

---

## Automation and Persistence Strategy
- **Mirroring**: Because CI calls `make check`, which in turn calls `scripts/check.sh`, there is zero divergence between what a developer sees and what the CI enforces.
- **Auto-Correction**: Future stages can expand `scripts/check.sh` to include a `fix` mode (e.g., `shfmt -w .`) to automate the remediation of formatting issues.

---

## Execution Instructions for AI Agents
1. **Dependencies**: Do not attempt to run checks if tools are missing; report the missing dependency and provide the installation command.
2. **Surgical Makefile Edits**: Use the `replace` tool to update the `Makefile` to avoid breaking existing installation targets.
3. **Verification**: After implementation, run `make check` to verify the new infrastructure.
